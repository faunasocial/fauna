# The feature catalog

One page per feature: what a person gets, and the tests that witness it. `MATRIX.md`,
each page's `## Status` block and `matrix.json` are generated by `just features-render`
from these pages and from the ledger the test runs write — no mark here is typed by
hand. The ledger is the maintainers' bookkeeping and is not part of this tree, so the
render and the lint that checks it run in the maintainers' tree; what ships is the
committed result. A witness written as `(maintainer-only)` is a test that proves the
outcome but does not ship — it needs live infrastructure or tooling of the maintainers'
own — so the page says so rather than pointing at a file you do not have.

`docs/features/` is the **published catalog** — what the product does. `docs/goal/`
is the specification — how it is meant to work. The two never restate each other: a
page points at the goal section that owns its mechanism, and the goal docs describe
mechanisms, never coverage.

The format, the coverage-contract grammar and the six lint rules are owned by
[`../goal/architecture/feature-catalog.md`](../goal/architecture/feature-catalog.md).
