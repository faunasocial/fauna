# Feature matrix

Generated by `just features-render` from every page in this directory and
the ledger the test runs write. Nothing here is typed by hand.

✅ every outcome in the feature's contract is mapped to a test and every
one of those tests passed for that app &middot; ⚠ the contract has an
outcome no test witnesses yet, the mapped tests are mixed, or a test needed something
not yet built while another failed &middot;
❌ tests witness this feature and none of them passed, and none of them
reported missing build work &middot; 🚧 at its last run, one of the
feature's tests needed something not yet built for that app (a part of the app, or the
test tooling that drives it), and nothing else on that cell failed — the work the mark
points to is building, not fixing &middot; *(blank)* our records hold no run for this feature and app &middot; —
the feature is absent on that app by design, and the page says where that is written.

Each cell carries the stamp of the nest artifact its tests were witnessed against (where
one complete run spanned two artifacts, the older of them): `<version> <nest mode>` means
the released artifact carrying that version, and `<version>-dev+<commit> <nest mode>`
means a build of that commit. `.dirty` after the commit means the run's working tree
carried uncommitted changes when it was collected, so that commit is a lower bound on the
code it saw — the next run from a clean tree supersedes it.

## Releases

One row per nest image build the catalog has something to say about. **Commit** is the development commit the release is keyed on; **Public commit**, when present, is the commit in the public repository whose tree — published from that development commit — the image was built from. **Verified** is the date the build's verify gate went green on the staging box. **Candidate run** is the date of its newest release-candidate run, the record the tag gate reads. **Promoted** says the build became the public `:latest`. A release is a train — the nest and all seven apps ship together at one version — so **Apps** is empty on an ordinary release and names only an app whose shipped version differs, which happens when a store-mechanical re-upload ships that one app at a later patch.
