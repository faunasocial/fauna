## The convention — convention 17 (== point 17)

17. **Hand-authored journeys are necessary, never sufficient — walk the UI systematically and assert GENERAL invariants (ratified 2026-08-03).** Every hand-authored test drives ONE path and asserts ONE hand-picked outcome, so a defect in a state nobody wrote a test for violates no assertion any test makes — three live-user-found tui bugs (a focus-paint id-collision, a sidebar-return stale sub-page, an unreachable empty-state dead end) each survived a green 1147-test suite exactly this way, and adding hand-written tests closes instances, not the class. The methodology is three layers, tiered downward by the same logic convention 14 applies to timer cadence: **(a) tier_1 in-process walks** wherever an app's state machine is directly drivable offline (reference: `apps/fauna-tui/src/walk.rs` over the offline `authed_app()` fixture) — exhaustive sweeps over the enumerable frontier (every page × every focus position × every sub-surface, reached through the *real* row gestures so no hand-listed enum can silently under-cover) plus **proptest** random walks past it (the workspace's ratified property-testing library, selection 2026-08-02) with shrinking to a minimal failing step sequence, asserting a small catalogue of GLOBAL invariants after every step (the focus affordance paints on exactly the focused line, the focus ring agrees with the element list, sidebar re-entry lands on the page's canonical entry state); **(b) a post-frame invariant checker** riding every existing e2e test over the driver-visible state surface (the reset-probe shape: fixture-attached, observing-not-failing until promoted — and **observing by DEFAULT since 2026-08-15**, env-overridable and env-disablable, because off-by-default meant the very corpus its promotion was gated on could never accumulate; § Implementation status today) — this alone would have caught the collision bug on any test that ever visited Settings; **(c) e2e-level walks** through generic agent commands (`focus_move`/`switch_pane` are tui's; convention-11 contract entries for the rest), scheduled sweeps only, never inner-loop. Three adoption disciplines make it trustworthy: **invariants are few and true-by-construction** (a checker that cries wolf gets deleted; a candidate failing on any reachable legitimate state is not an invariant — each names the bug class it catches); **walks drive the real input doors** (keystroke/click handlers, never private seams — the stale-sub-page bug lived precisely in the human-path/agent-path difference, so an agent-path walk structurally could not see it); **fixtures must not seed past the frontier under test** (pre-seeding state through raw RPC is exactly why the empty-set journey was never driven — first-use/empty states are walk territory). **Red-verification is part of adoption** (convention 11's mutation-verify applied here): a new invariant or walk demonstrably catches a known, temporarily-reverted defect before it counts as coverage — measured 2026-08-03: the id-comparison revert redded 3 of the 4 walk tests including a collision on a page no user ever reported, and shrank to a 3-step repro; the bare-page-write revert redded exactly the canonical-entry sweep. Layer (a) is BUILT on tui and on **linux** (2026-08-13 — § Implementation status today); layer (b) is BUILT and rides the `app` fixture observe-only (2026-08-15), all three of its invariants red-verified against a live mutated tui run (§ Implementation status today); layer (c) is BUILT (2026-08-16) — the two walk commands are convention-11 contract entries in `fauna_e2e_agent`, honoured natively on tui and linux, and the sweep runner lives behind the `--walk-sweep` prune-gate (§ Implementation status today). The remaining apps' (a)-legs and (c)-legs, and the snapshot-layer cross-surface consistency properties the dead-end class additionally needs, are queued (tracked internally). Design record + demonstration outputs tracked internally (2026-08-03).

## Implementation status today

- **Convention 17 layer (a) — the linux leg BUILT 2026-08-13, and it found two defects on its first run.** `apps/fauna-linux/src/walk.rs` is the GUI twin of tui's `walk.rs`: it builds the real `build_main_window` over an offline client (a closed port), presents it on the private Xvfb display `testid::run_on_gtk_thread` owns, and sweeps every surface a user can reach through the **real doors** — `select_row` on the main sidebar (13 pages, the gated Admin/Family rows revealed through their own `show_*_sidebar_row`) and `row-activated` on each shell's nav rail (24 Settings + 13 Admin sub-pages). Three facts about it are load-bearing for the other apps' legs. **(a) It reads the surface through the agent's own `automation::find::is_showing`**, so a surface the walk calls reachable is one the driver really resolves — the GUI analogue of tui's walk reusing paint's own `element_lines` call. **(b) The window must actually be presented.** GTK's `is_visible()` is ancestor-aware up to the toplevel, so an unshown window reports *every* descendant hidden: the walk's first run measured 0 showing ids on all 13 pages and would have passed vacuously forever. `the_walk_sees_a_real_surface` is the guard that keeps that from silently recurring — any GUI leg needs its own. **(c) The rail sweeps are coverage the e2e suite structurally cannot have**: both shell rails build bare icon+label rows with no test id (`views/nav_rail.rs`), exactly as tui's Settings rail does, so the pytest suite's only route to a sub-page is the `nav` patch — which names the sub-page directly and therefore can never discover a mis-wired rail row. The invariants are two, both true by construction of the ID contract: **a non-indexed id never resolves to more than one showing widget** (`find` returns the first match, so a second widget wearing the id makes every read a coin flip decided by tree order; the exception set is read from ui.yaml's own `indexed: true` registry entries rather than restated in Rust), and **every reachable surface shows a heading**. **First-run findings.** (1) `admin-web-heading` was built `visible(false)` with no text — an invisible shim (point 1 bans them) that `find`'s pruning made unreachable by any driver read, while ui.yaml scopes it as that page's title text and ios/windows/tui all render one; **fixed** in the same change, which is what turned the Admin sweep green. (2) Eight Settings sub-pages show the user no heading at all — each is an `adw::PreferencesPage` whose `.title(…)` renders only inside an `adw::PreferencesWindow`, so inside the shell's plain sub-stack it is metadata nothing paints; a real conformance gap against § global's `page-heading` rule, pinned by an equality-checked known-gap list (not a count, so fixing one also reds) and captured for a cross-app ruling rather than fixed in passing. (3) Measured and **not** ruled: linux does not reset the shell on re-entry the way tui's nav-edge reset does — `ui/settings.md` § Navigation model and `ui/README.md` are both silent on what re-entry lands on, so the walk pins only what holds under either ruling (re-entry is deterministic, and lands on a live surface). **Red-verified per this convention's adoption discipline — four mutants, each caught by the right test with a diagnostic naming the defect:** a second widget wearing an existing non-indexed id (three sweeps red, naming the id and its count); a top-level page's `page-heading` renamed away (sweep 1 red, naming the page); a *ninth* headless Settings sub-page (the equality-pinned list red, telling the reader which direction to fix); and the fixture left unpresented (the vacuity guard red — and the sweeps refuse to run at all rather than pass over empty id lists, which is the failure mode that would otherwise make this whole module decorative).

- **Convention 17 layer (b) — the post-frame invariant checker is BUILT, wired and RED-VERIFIED 2026-08-15, riding the fixture observe-only.** `tests/e2e-unified/helpers/frame_invariants.py` + the `app` fixture's teardown: env-gated on `FAUNA_E2E_FRAME_INVARIANTS=<path>` (off by default, one state read when on), writing a trace FILE, never failing the run it observes; `FAUNA_E2E_FRAME_INVARIANTS_STRICT` exists so promotion-to-failing is a switch rather than a rewrite, and is deliberately unset — promotion is gated on a clean full `--app sweep`. The catalogue is three entries, each naming its bug class: **`focus-fanout`** (`focused_line_count <= 1` — the focus-paint identity collision), **`messages-readable`** (`messages` a mapping, `error` text-or-null — the error surface losing the shape conventions 2 and 6 both read through), **`nav-stack`** (non-empty, every entry names a view — the dead-end / stale-sub-page structural signature). ⚠ **The bound is `<= 1`, not `== 1`**, and that is the whole reason the layer is survivable: a fresh authenticated tui session sits in `Zone::Sidebar`, where the page's focus ring does not hold the keyboard and the count legitimately reads **0** (`test_tui_settings_focus.py` calls `switch_pane` precisely to get off it), so an `== 1` checker fires on most of the suite, is correctly called noise, and takes the layer with it — `test_zero_focused_lines_is_not_a_violation` exists to stop that regression. Cross-app safe from day one: an app publishing no such field is `n/a`, never a violation. ⚠ **But `n/a` is not by itself a queued leg — for `focus-fanout` it is a permanent, reasoned property, RULED 2026-08-15.** tui is the only app that paints its own focus affordance, because it is the only one without a toolkit that owns focus: GTK, the DOM, WinUI, SwiftUI and Compose each guarantee at most one focused element per root, so the identity-collision class cannot arise there. Audited rather than assumed — linux only ever *requests* focus (`grab_focus`; no hand-painted highlight anywhere), web paints with declarative `class:selected` over unique value keys, apple does not even use SwiftUI `FocusState`, and no app but tui publishes the field. The generalised class is *"an affordance painted by comparing on a key that is not unique per element"*: tui's key was `element.id`, blank on ~19 Settings rows at once, while the GUI apps' nearest equivalents (a date tuple in the mini-month, a calendar id in the sidebar) are unique by construction and clear the class on non-matches. **So the six other apps owe no `focused_line_count` twin**, and the portable catalogue for a toolkit app is the two shape invariants — both of which linux already satisfies today, since it publishes `messages` and `nav` and is therefore covered by this checker with no per-app work at all. **Red-verified on a live tui process, all three, from one mutated build** (they read independent state keys): reverting the id-string comparison of that fix gave `focus-fanout: 22 lines paint focused at once`; emitting `messages` as a bare value gave `messages is NoneType, not a mapping`; emitting `nav.stack` empty gave `nav.stack is empty`. Baseline on the clean build: `OK`, no `n/a`. **The thesis reproduced:** `test_settings.py::test_inbox_mode_toggle` — which asserts nothing about focus, messages or nav — **passed** against the mutated app while the probe recorded two violations on its final frame. And `focus-fanout` correctly stayed *silent* on that frame, because that test never enters the page zone and the count is legitimately 0 — the `<= 1` ruling proving itself on a mutated build, where `== 1` would have produced a false positive on a healthy frame. ⚠ **The verification found a defect in the checker itself, which is the whole argument for the discipline:** `state.get(k)` collapsed *"this app does not publish k"* and *"k is present and null"* into one answer, so the `messages` mutation first reported `n/a` — declining to catch the defect it was aimed at — while 20 tier_1 tests over synthetic dicts stayed green throughout. A checker answering `n/a` where it owes a violation is a clean bill of health for a broken app. Fixed with an `_ABSENT` sentinel at all four lookup sites and pinned (`test_a_published_null_is_a_violation_not_an_absence` + two siblings, 23 tier_1 tests total). **Observation became the DEFAULT the same day, and that reversal is the load-bearing correction:** as shipped in the morning the probe was off unless `FAUNA_E2E_FRAME_INVARIANTS` named a file, with promotion gated on *"a clean full `--app sweep`"*, and both halves were then measured against each other. So: `FAUNA_E2E_FRAME_INVARIANTS` unset now **observes** into a per-checkout gitignored corpus beside the harness (`helpers/frame_invariants.py::DEFAULT_CORPUS_NAME` = `tests/e2e-unified/.frame-invariants.log`, ~300 KB per full sweep at ~120 bytes a line); a path still redirects it verbatim; and an off-token (`0`/`off`/`no`/`false`/empty) disables it, because a probe that cannot be switched off is one bad day from being deleted outright. **What makes default-on safe is the half that did not change** — the probe still swallows every failure mode and never fails the run it observes (`FAUNA_E2E_FRAME_INVARIANTS_STRICT` remains the promotion switch, still unset). **And a corpus nobody opens is still no observation, so the run now reports its own verdict**: `pytest_terminal_summary` prints one line — frames observed, frames violated, unobserved count, corpus path — plus up to `SUMMARY_DETAIL_CAP` named offenders.
