## Serialized switching — completing the isolation contract

The remediation for today's actor-blind surfaces (ratified 2026-07-22):
**per-account paths, uniformly on all seven apps.** Each store listed in the
gap ledger (§ Implementation status) moves under the account-scoped layout.
**Nothing is adopted from the flat base:** a store sitting flat at a base is no
account's. (Pre-existing flat data was once adopted copy-never-destroy by the
account active at upgrade through one shared first-adopter mechanism — the
`state-owner` marker — until the compat-remnant sweep retired it (`../compat-remnant-sweep.md` § Program 4, tranche B1, 2026-09-25); no pre-sweep installation
exists to serve.) Specifics:

- **MLS state** (today one fixed SQLite file per app) becomes
  `<state base>/<actor-id-hex>/mls.db`. The engine layer already accepts an
  arbitrary path (`MlsEngine::new(identity, db_path)`); only call sites
  change.
- **Content databases and caches** (android's Room DB, per-app content
  caches, spam replicas, backup-coordinator state, P2P peer state) take
  account-scoped placement as class-1/class-4 data. Where a store is a pure
  class-4 replica, wiping is acceptable with a one-line recreatability note,
  but per-account placement is still the end state —
  wipe-on-switch is not a substitute for scoping (it destroys offline access
  and re-downloads on every switch). **The segment-backup coordinator's state
  was this carve-out's example on every app** through the account-scoping
  ledger below's original closures (per-(destination, segment) upload state,
  the manifest mirror, per-destination engine scratch — wholly re-derivable
  from the source nest and the destination's own manifest) — **the in-app segment-backup upload driver itself was later
  deleted fleet-wide** (the source nest is the writer now;
  [`../../behavior/backup-restore.md`](../../behavior/backup-restore.md)
  § Background Tasks → *Flip status (slice 5)*, COMPLETE 2026-08-16), so no
  client opens that dir any more and the ledger rows below describing it are
  historical (what was true when each closed), not a live surface to check.
- **Preferences split by meaning, not by file:** device facts (theme, window
  geometry, tray behavior, autostart) stay install-scoped; person-facts
  (anything that would surprise a second account — e.g. drafts, notification
  choices tied to an identity) are account-scoped.
- The identity secret and anything reachable only through it remain governed
  by the never-delete rule (`../../principles.md` § No user-data loss).

## Implementation status today

The closure record's entries, carried verbatim out of [`account-scoping.md`](account-scoping.md) § Implementation status today on 2026-09-28 in their original order.

**Serialized-switching isolation — the PERSISTED dimension:** **all seven apps are
complete** — apple, linux, tui and android 2026-07-22 (apple closed its gap-ledger
row first), and **windows 2026-07-23** (the last leg: MLS + feed-compose drafts
scoped + adopted, backup coordinator scoped as the class-4 carve-out, sign-out +
remove-account erasure, all through `FaunaApp.Core.Services.AccountStateDir`). The
**in-memory** dimension is a separate question, and as of **2026-08-27** it is
complete on all seven — windows closed 2026-08-24 on the shape linux ruled and
apple adopted (one explicit drop per app, never a registry); tui, which this
paragraph had counted as closed without a row, was found open and closed
2026-08-27 (the drop was complete; what leaked sat *below* it, in shared Rust
and in tick-bound loops the drop could not reach); and **android, caught the
same day by the same "counted closed without a row" audit, was open too and
closed 2026-08-27**. android's root was the inverse of the other four: not one
drop hand-listed at N sites, but two teardown funnels and no rule saying which a
new surface joined, so two of its sites ran no closer at all and four
actor-scoped surfaces were on neither. Its live holder was the foreground
custodian push-debounce loop, which shared Rust documents as unable to self-exit
when its source disconnects and which android cancelled only on *backgrounding*
— an event an in-app account switch is not. See the Isolation-contract gap
ledger's `<app> (in-memory)` rows for each leg.
The shared mechanism is the derivation plus erasure, in
`fauna_sync_engine::db`: `actor_state_dir` (and its
`actor_state_dir_or_unresolved` degrade, which lands a malformed id under the
`-unresolved-` component, never the base) places every store, and
`erase_account_scope` / `erase_all_account_scopes` implement *Erasure follows
scope*. The all-accounts form drops every actor scope and nothing else. Since
2026-09-09 it returns an `EraseSweep` {`erased`, `survivors`} instead of
`Result<usize>` and no longer stops at the first scope it cannot remove
(§ Erasure follows scope's ⚠ corollary). Pinned by
`db.rs::a_scope_that_will_not_go_is_reported_and_does_not_abandon_the_others`,
which injects the fault with a **read-only parent** — POSIX `unlink` removes an
open file, so the windows-only held-handle shape proves nothing on linux — and
is mutation-verified against both the un-named-survivor and the
abandon-the-rest regressions. The first-adopter adopters
(`adopt_flat_db_for_actor`, `adopt_stores_for_actor`, `adopt_state_for_actor`
and the `state-owner` marker) and the erase's flat-copy arm were retired by the
compat-remnant sweep (`../compat-remnant-sweep.md` § Program 4, tranche
B1, 2026-09-25) together with their FFI exports; apple's and android's
own flat-path fallbacks are those apps' remaining legs of the same sweep.

One known gap, not blocking a leg:

- **The scoped MLS filename is not uniform.** apple, android and windows write
  `<actor-hex>/mls.db` (the name this section specifies); linux and tui kept
  `mls_state.db` when they scoped. Placement is correct on all five — only the leaf
  name diverges. Worth unifying on `mls.db` when a session is next in that code
  (priority #4), not worth a dedicated churn commit.

Anything that is not an actor scope stays put — that is how install-scoped
class-2 state (logs, host-keyed TOFU pin stores) survives sign-out. Apps reach
the set through `libs/fauna-ffi/src/account_state.rs` (`account_state_dir`,
`account_state_erase_scope`, `account_state_erase_all_scopes`). Apple's
client-side shape (`FaunaKit/Core/AccountStateDir.swift`) is the reference: one
type owning the base, the per-store paths and the erasure entry points;
android's `core/AccountStores.kt` is the same shape for a platform with **two**
state roots (`filesDir` and the Room `databases/` dir), each scoped by its own
call.
