## The convention — convention 16 (== point 16)

16. **A live sync-convergence test defaults to TWO SEATS ON ONE MACHINE, no operator (ratified 2026-08-01, user-directed; extended to N seats 2026-08-02).** The operator-coordinated tri-machine round (`test_filesync_multiseat_live.py` § THE OPERATOR HANDSHAKE) costs three humans-at-machines per run and therefore cannot be the workhorse shape for sync tests. The default shape is instead: one pytest process starts **two independent sync seats on one machine** — same account seed, two per-`sync.db` device ids (the laptop+tablet scenario the engine mints ids for, `libs/fauna-sync-engine/src/config.rs::device_id`), two isolated watch dirs — against the **live nest**, and asserts convergence directly (write on A, deadline-poll B, and back; concurrent-edit merge; delete propagation as the cleanup leg). tier_4 by the live-remote ruling (§ taxonomy point 4). Seats are parametrized per-seat over two drivers — **tui** and the **platform-native app** (UI seats do sign-in/adopt/bind through the real UI, importing the app round's steps, then the subject is plain file I/O — the user path for sync). A third, **disk-only** driver (a headless `fauna-sync` daemon, the convention-8-rider control) is **retired since 2026-09-30**: the nest refuses every record the daemon's unsigned legacy data plane sends ([`mls-group-key-material.md`](mls-group-key-material.md) § Implementation status today, the legacy-daemon residual), so a daemon seat cannot converge, and no app-free seat can sign — the agent's change signer is the principal writer key only an app's enrollment certifies. Four load-bearing consequences: **(a)** the tri-machine ceremony is coordination for machines that cannot see each other and is dropped, not ported — no announce/`YYYYMMDD-NN` id (a local `2seat-<date>-<hex>` token, disjoint from the announce regex, is fresh by construction), no `go`-wait, no hello/ready rendezvous, no `ASSEMBLY_WINDOW`; **(b)** because the only channel between the two folders is the nest, a peer-side observation IS the writer's upload proof, so the own-ack barrier survives only as failure diagnostics; **(c)** an unattended run against example.com is licensed solely by the shared-box rule's non-destructive carve-out ([`testing.md`](testing.md) § The shared-box rule) — the run creates only uniquely-named `<token>-*` files and **must delete them in an assertive cleanup leg** (barriered on the peer applying the deletes) with the blast-radius argument in the test docstring; **(d)** the tri-machine round is NOT retired — it becomes the *certification* run for what one machine cannot prove (cross-OS path/filesystem heterogeneity, real cross-machine network + staggering, the other platforms' agent-spawn seams), and its explicit-`go` iron-clad is untouched by this convention — and since 2026-08-03 that iron-clad is **mechanically enforced, not merely documented**: every `live_box`-marked test (the tri-machine round included) is skipped by conftest's autouse `_live_box_opt_in_gate` unless `FAUNA_E2E_LIVE=1` or `--nest live` opts in, so no default sweep can reach the shared box. The gate is keyed on the marker rather than hand-rolled per module because the hand-rolled version is what failed: both tri-machine modules gated on the account seed `~/.fauna-id` merely *existing* — true on every dev machine — so a plain `--app tui` sweep signed in to the live box and ran the seat steps unattended, and two independent >1h sweeps filed the resulting failures as regressions on already-closed items. Pinned by `tests/test_live_box_opt_in_gate.py`. The full design + evidence trail (every scoping question answered with file:line from current code) is tracked internally (ratified 2026-08-01). **Seat count is a parameter, and THREE seats is the fan-out certification (user-directed 2026-08-02).** Two seats can only ever state *pairwise* facts, while a real account has more than two devices, so the shape generalizes to N ≥ 2 and three adds exactly the three properties two cannot express: **(i) fan-out** — a write must reach *every* peer, not "the other one" (the hello leg is n(n−1) observations, so three seats owe six including `a → c`; a delivery rail that fanned out only to the first-registered device passes the two-seat test and fails a real account); **(ii) a merge of TWO remote edits** — each seat folds two independent concurrent edits into its own from the common base and all three must land on identical bytes, the case where an engine that resolves pairwise but not transitively diverges; **(iii) delete propagation to more than one peer** — a tombstone reaching one device and not another is invisible to a two-seat run. The load-bearing implementation rule: the legs are written over the seat *list* and the fan-out is **enumerated** (`convergence_legs.hello_fanout_plan` / `peers`, tier_1-pinned), never neighbour-indexed — reusing a pairwise leg body is how a three-seat assertion silently narrows into two pairwise ones that never check `a → c`, and it would report green. Timeout ceilings derive from `convergence_legs.await_count(n)` rather than a hand-counted leg number. Everything else is unchanged and shared across seat counts: the seat seam, the run-file protocol, the no-operator/no-announce discipline, and the assertive cleanup — the only additions are a seat-count-leading run token (`2seat-`/`3seat-`, still disjoint from the announce's `YYYYMMDD-NN` namespace by construction, so residue names the run shape that left it) and one extra device row per extra seat, the same accepted side effect the two-seat shape already carries. The 2026-08-01 standing authorization to run unattended against the live box was granted for the two-seat shape; the user directed the three-seat extension on 2026-08-02 under the same recorded rationale, and it covers **that shape only** — every other live-box mutation class, and the tri-machine round's explicit-`go` iron-clad, are untouched.

The one-machine leg escapes that for free (one pytest process sequences the delete strictly after convergence); across machines there is no such process, so phase 5 buys the ordering with an explicit causal barrier — **5a** every seat publishes `<ID>-seen-<seat>.txt`, which it may write only once its phase-4 wait returned, i.e. only once it holds every peer's done file; **5b** a seat unlinks its OWN done file only after observing every peer's seen file, which is proof each peer already holds what is about to disappear. Each seat deleting only its own file makes three tombstones apply on two peers apiece, so one round covers every ordered (recording OS → applying OS) pair — the certification a single machine cannot give, and [`../behavior/file-sync.md`](../behavior/file-sync.md) § *Applying a remote delete must not record one back* is why it must be cross-OS: the echo-suppression token collision is reachable on macOS's event latency and not on Linux's.
