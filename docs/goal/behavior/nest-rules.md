## Goal

A nest admin publishes **blocking rules** for their nest — the same kind of instrument a government publishes for a region and a guardian sets for a child — and the member's own device applies them to what reaches the member through that nest, visibly, naming the rule. The admin never picks an item and never sees content; a rule only ever adds to the member's own filters; joining a nest is accepting its rules. One rule editor, shared Rust under one UI shape on all 7 apps, serves all three publishers.

## The owner's direction and decisions (2026-10-16)

The frame is the owner's ([`../architecture/public-texts.md`](../architecture/public-texts.md) § Words from the owner): three actors — governments, guardians, nest admins — may block other users' content; all three by **rules** (simple rules, or prompts for on-device LLMs), under which governments and guardians never see the content; only an admin by **manual blocking**, and only on a legal takedown or on a user's report, seeing only what is plaintext on the nest; blocking is always additive and visible with an explanation. The per-nest rules are the admin's rules instrument. Four decisions the design pass put to the owner, each taken as recommended ("Your recommendations for all four"):

1. **The `prompt` rule kind is admitted now, inert until a runtime exists.** The grammar carries a prompt for an on-device LLM so all three publishers can author one; a device with no runtime applies every other rule of the document and shows the prompt rules as *not applied on this device* on the transparency surface. The runtime is its own design, and its model runtime a dependency for the bump queue; whether a prompt rule is a realistic instrument at all is weighed first.
2. **Content-id lists are a government's instrument only.** A region document keeps its `list` scorer (published in full in the transparency log, an exact-bytes lookup). A nest document and a guardian document bundling a `list` scorer are **malformed**: for an admin a list of ids is manual blocking without the notice naming a report, the appeal and the record ([`takedown-and-block.md`](takedown-and-block.md) § Admin block of a reported item is the path for one item); for a guardian, who never sees the content, there is nothing to list.
3. **Attribution on a tie goes region, then nest, then guardian.** When two sources reach the same winning strictness, the placeholder names the region's authority first (a reason the user is entitled to read), then the nest (the party the user accepted at joining), then the household.
4. **Scope and binding.** A nest's rules bind everything the member reads **through that nest** and nothing read through another nest the same app is signed into; a member may add filters and never loosen a nest's rule; the nest applies its own rules to what it publishes off-box exactly as a region's apply there (the publisher leg); joining shows the rules above the terms notice, and a later change is announced to members. The policy is signed by the nest, not enrolled in the transparency log — a nest is not an authority, and its members can leave.

## The nest content policy

- **One grammar, three publishers.** The document is the content-policy grammar [`region-blocking.md`](region-blocking.md) § The policy document owns — `version`, `rules { factor, min_permille, verdict, reason_code, reason }`, optional `scorers` — with a **publisher** namespace on scorer factors: `region:<region>/<name>`, `nest:<domain>/<name>`, `guardian:<name>`. The structural validator is one shared module (`fauna_core::content_policy`, generalised from `region_policy`, which keeps its name as the region's assembler) taking the publisher, so the per-publisher admissions (decision 2; a `list` only for a region) are one check in one place. A `reason` is required on every rule for every publisher, and it is for the person the rule binds, whoever published it (§ The shared rule editor → *The reason is the member's to read*): the member reads the nest's reason verbatim under the app's frame, as they read an authority's — and a ward reads a guardian's the same way.
- **Rules only.** A nest document is categories, thresholds, keyword rules, labeler subscriptions and prompts — never an item. The admin's block of one item is the report queue's verb and the takedown console's, both by hand with the transparency triple; a rule is neither ([`moderation.md`](moderation.md) § Categories & enforcement item 1: a published rule applied on the device is not a removal).
- **Nest state, written in the app.** The document is admin-written nest state (the one-configuration-surface invariant, bucket 2), persisted beside the other nest-wide documents the admin authors (the feature-limits precedent — [`../architecture/dynamic-features.md`](../architecture/dynamic-features.md) § Authoring surfaces), never a file. Wire: `fauna.admin.content_policy.get` / `fauna.admin.content_policy.set { document }`, Admin class, admin-signed like `fauna.admin.region.set`; the nest validates structurally with the shared module before storing and refuses a malformed document with the defect named (the editor pre-validates with the same module, so a refusal is a defence, not the UX). Each accepted write stamps a monotonic `sequence` and `issued_at`, and the nest signs the canonical document with its identity key (`SignedContentPolicy { document, sequence, issued_at, signature }`) so a member can show what rules were in force when.
- **Carriage — the self-description.** `NestInfoReply.moderation.content_policy: Option<SignedContentPolicy>` — the `ModerationInfo` slot the house-rules design reserved, which carries nothing today; additive, `#[serde(default)]`. The per-connection memo already carries the self-description with no new round trip ([`../architecture/transport-trust.md`](../architecture/transport-trust.md) § The nest's self-description); the device verifies the signature against the nest's identity and keeps the **last-accepted document per nest** with its sequence, so a rule change is detectable (below) and an unreadable answer leaves the last-known rules in force — the region plane's fail posture, same reasons.
- **The nest source in the engine.** `rules_from_nest_policy(document, nest_domain) → NestRuleSet` mirrors `rules_from_region_policy`: the nest's domain, the document's `PolicyStatus`, and rules each carrying their own `reason_code` + `{ lang → text }`. The composed call ([`family-client-enforcement.md`](family-client-enforcement.md) § Content policy) gains one more slice argument — the rule sets of the nest the item was **read through** (one, ordinarily) — folded separately like the others; `ComposedVerdict.source` gains a nest arm naming the domain; the precedence `Block > Collapse > Badge > Show` is untouched; the tie goes by decision 3. No second engine, no surface reaching the composed call for one source and bypassing it for another.
- **Which nest an item was read through** is a fact every read already has — the connection the post, conversation record or projection arrived on. Shared Rust carries it on the item's render input (the feed read model, the conversations render, post detail), never re-derived per app from the author's handle: a federated post the viewer reads through nest A is under A's rules even when its author lives on nest B, and the same post read through nest B is under B's.
- **Additive, never loosenable.** The member's own thresholds and muted keywords compose beside the nest's rules; strictest wins. There is no member-side override of a nest rule, no "show anyway" past a `block` — a `collapse` keeps the engine's reveal affordance, as a region's does.
- **The publisher leg.** The nest applies its own document to the public web pages it renders from public posts, through the same composed engine with the nest source, exactly as [`region-blocking.md`](region-blocking.md) § The nest-as-publisher leg applies the situs's region policy there; the page shows the same placeholder naming the nest and the rule's reason. No other nest surface evaluates anything.
- **The keyword rule.** A published keyword rule is a `keywords` scorer in the document — a UTF-8 list of terms, matched by the one shared deterministic matcher the muted-keyword path already uses (`fauna_core::keyword::body_excludes_matches`, case-insensitive substring, OR across terms; owner [`../architecture/content-moderation-and-ranking.md`](../architecture/content-moderation-and-ranking.md) § Composition), producing the factor `<publisher>/<name>` at 1000 on a match, run post-decrypt on the device and over public plaintext on the publisher leg. It is a different thing from the member's own muted keywords ([`moderation.md`](moderation.md) § Muted keywords): theirs is a sealed, private, penalty scorer on their own list; the nest's is a published rule with a reason the blocked reader sees. The two never merge.
- **The labeler rule** is a `wasm` scorer exactly as the region grammar admits it; **the prompt rule** is a `prompt` scorer (UTF-8 prompt text) under decision 1.

## Acceptance at joining, and a change of rules

- **Joining is acceptance.** `invite_request` renders the nest's rules — per rule the verdict and the reason text, in the member's language where the document has it, else the default — **above the by-continuing terms notice** ([`terms-and-content-guidelines.md`](terms-and-content-guidelines.md) § The decisions, the notice's placement stands); an empty document renders nothing. A document none of which applies on this device (`NestRulesSummary::not_applied` set) is not an empty one: the heading and the reason's sentence render, under the heading, whether or not any rule is listed — a newer grammar's document decodes to no rules here, and joining still accepts it; the settings rules surface paints the same sentence. The same rendering, above the same notice, on `handle_entry` while its Continue signs in (`terms_notice_visible`, [`onboarding.md`](onboarding.md) § 2) — the first sign-in of a user the admin admitted directly, who never sees `invite_request` (decision 3 (iv) of the terms doc, amended 2026-10-19); a returning sign-in on a new device reads the rules again, which costs one screen. The eighth content guideline, "your nest's rules", is this document.
- **A change is announced.** On an accepted write the nest invalidates the self-description memo for every connected member (an additive `StaleSurfaces::nest_info` flag on the reconnect-and-push seam, [`../architecture/transport.md`](../architecture/transport.md) § Push events) and the device, finding a sequence newer than its last-accepted, shows a one-line notice naming the nest with a way to the rules surface; the new rules bind from that read. A member who disagrees leaves — there is no per-member opt-out, by decision 4.
- **The rules surface.** The settings page shows, per signed-in nest, the rules in force (verdict, level, reason), the sequence and issued-at, and any rule not applied on this device (decision 1) — mirroring the region plane's transparency surface.

## The shared rule editor

- **One model, shared Rust.** A new crate `fauna-client-policy` holds the editor's model: load a document, edit it (add / remove a rule; per rule pick its kind, its subject, a verdict, a level, and write the reason text with a required default), validate it with the shared structural module for the mounting's publisher, and serialise it. The per-mille threshold is shown as a plain **level** (a small named scale, the shared constant's value as the default) and stored as per-mille. Exported over UniFFI and wasm; every rendering decision — the kind list, the level labels, the defect sentences, the "not applied on this device" wording — is the crate's, so the six-app trickle-down after tui is paint-only (priority #2).
- **Rule kinds the editor offers:** a **category** rule (one of the canonical `nsfw` / `spam` / `phishing` / `commercial`, or a factor a bundled scorer of this document produces); a **keywords** rule; a **labeler** rule (a subscribed labeler the publisher bundles as a `wasm` scorer); a **prompt** rule. The `list` kind is not offered by the editor to any publisher — a government's list is published through the authority tooling, not typed in an editor.
- **Three mountings, one shape.** (a) **The admin's**, on `admin-nest` directly after the reports queue (placement [`admin.md`](admin.md) § N. Nest), writing `fauna.admin.content_policy.set`. (b) **The guardian's**, in the per-selected-ward policy editor on the `family` page, **replacing** the four `family-policy-content-*-select` floors: the guardian policy document gains an additive rule document (`ContentPolicy.document: Option<ContentPolicyDocument>`, publisher `guardian`), whose rules the engine's guardian source reads beside any floor still set (`rules_from_guardian_policy`; storing a document clears the floors, so for a policy written in the editor the document is the whole rule set); the editor writes the document; the floors retire from the wire once all 7 apps mount the editor (the 0.1.x window owes no compat; if the window has closed by then the floors stay as the older-client degrade). The guardian gains the editor's level control, superseding the v1.x "no per-category confidence knob" as the bounded amendment that section itself reserved; the honest-bound caption (a rule on an unproduced category is stored and waiting) stands. (c) **The authority's**, in the authority authoring path the government-moderation track owns, producing the same document for signing and publication through that plumbing — the host ID is that track's.
- **The reason is the member's to read, in every mounting (ruled 2026-10-19).** The one grammar requires a `reason` on every rule, and the editor labels the field *Reason shown to the member* (`rule_editor.reason_label`) for every publisher; the label is a promise, and it holds in all three mountings: a region's reason is the authority's, read verbatim ([`region-blocking.md`](region-blocking.md) § The content plane, invariant 1), a nest's is the admin's, read verbatim beside the `nest_rules.*` frame, and **a guardian's is read by the ward** — verbatim beside the family-policy frame on the placeholder (block and collapse alike) and on the read-only `family-policy-summary` line of the rule that carries it. Why: the owner's frame makes blocking by all three actors *visible to the user, with an explanation* ([`../architecture/public-texts.md`](../architecture/public-texts.md) § Words from the owner); supervision is transparent by construction ([`family-safety.md`](family-safety.md) § The trust shape, invariant 4); and a required field nobody reads is a private note, which the one validator would have to make optional for one publisher alone — a per-publisher divergence for nothing. What the ruling leaves as it is: the frame stays the app's (`family.content_blocked_notice` / `.content_collapsed_notice`), the reason beside it and never inside it, as a nest's; a floor still set from the retiring selects, a document this build cannot apply and the kids compiled floor carry no reason and paint the frame alone; the tie order (decision 3) and Guardian Notify are untouched; the ward's reason element mirrors `nest-blocked-reason` (ui.yaml owns the id, proposed under rule A with the tui leg). The engine consequence — the composed verdict's guardian arm carrying the rule's `reason_code` and `{ lang → text }` as the nest arm does — is [`family-client-enforcement.md`](family-client-enforcement.md) § Content policy's; the build is rust-first (§ Implementation status today).
- **What the editor never does:** show content, accept a content id, or offer a verdict the engine lacks (`block` | `collapse` only; the guardian's `inherit` is the absence of a rule).

## Where logic lives

Shared Rust owns every decision: the grammar and its per-publisher validation (`fauna_core::content_policy`), the nest assembler and the composed fold (`fauna_core::obligation`), the signed carriage type (`fauna-protocol`), the read-through-nest fact on render inputs (`fauna-client`), the editor model (`fauna-client-policy`), the joining and settings renders' row text. The apps paint: a list, selects, inputs, a notice. No app parses a document, picks a level label, or decides which nest an item came through.

## What the build owes in tests

tier_1: per-publisher validation (a nest or guardian document with a `list` scorer is malformed; a region one is not); `rules_from_nest_policy` composes into the existing fold with strictest-wins across all four sources and the decision-3 tie order; a prompt rule on a build with no runtime leaves the other rules applied and reports the inert rule; the keyword scorer matches as the muted-keyword matcher does; the editor model round-trips a document through every kind. tier_3, through the UI on tui first: an admin's rule blocks a post visibly with the nest named and the reason shown; a member cannot loosen it (their own threshold below the nest's changes nothing); a guardian floor set through the shared editor still binds and the family e2e stays green; a member joining sees the rules above the terms notice; a rule change reaches a connected member as a notice; the nest's public page shows the placeholder. Convention-17 invariant: a nest `Block` verdict never renders silent.

## Don't do these

- No second engine, no second fold, no per-app assembly of rules.
- No content-id anywhere in a nest or guardian document; no "block this item" affordance in the editor.
- No member-side override of a nest rule; no silent application — every block names the nest and the reason.
- No key, grant or plaintext for the admin or the guardian: rules run where plaintext legitimately exists, on the member's device and over public plaintext on the publisher leg.
- No hand-edited policy file, env var or CLI flag — the editor is the only way a document is written.
