## Goal

A user marks an email as spam in her app (or via `\Junk` in a third-party MUA). Because she opted in to report sharing (default off), her nest records the *fact of the flag* — keyed by a canonical hash of the message content, never the content itself. When ≥ k distinct local users have flagged the same content, the aggregate becomes readable: a transparent tier-3 `report:spam` factor on the scores bus, and an `(content-hash, factor, count)` entry peers may fetch over the federation channel. 100 opt-in reporters of the same campaign message = a strong, transparent signal — applied through each user's own thresholds (informs, never compels), aggregated per-nest, exchanged peer-to-peer only.

Below k, nothing is readable anywhere — not by the admin, not on any wire, not in any export. A reporter's identity never leaves her own nest at any count.

## Invariants (owned by the frame — applied here)

The six ratified invariants live in `../architecture/content-moderation-and-ranking.md` § Distributed report sharing: opt-in default-off per user; k-anonymity-before-existence; only `(content-hash, factor, count)` crosses any boundary; no central registry (per-nest aggregation, peer-to-peer exchange); peer counts never scale local consensus; the aggregate is a transparent tier-3 factor applied through the user's own thresholds. Every mechanism below is shaped by them; a change that weakens one is a frame change, not a report-sharing change.

## Content identity — the canonical report-hash

Cross-user aggregation needs a content-equality key that is identical for every recipient of the same message, on every nest. Fauna has no such key for mail today: `content_id`s are per-copy *addressing* keys (`blake3(content_type:natural_id)` — `bins/fauna-nest/src/db/mod.rs`), and Message-ID is sender-controlled (trivially randomized per recipient). This doc introduces one:

**`report_hash` v1 (mail):**

```
report_hash = blake3("fauna:report-hash:v1\0" ‖ canonical_text)
canonical_text = canon(Subject) ‖ "\n" ‖ canon(BodyText)
canon(s) = trim(collapse_ws(lowercase(nfc(s))))
```

- `Subject` and `BodyText` are the same parsed fields the index tokenizer already consumes (`ParsedMessage.Subject`/`.BodyText`; "the text of this message" has one answer). `collapse_ws` maps every Unicode-whitespace run to a single ASCII space.
- **Excluded by design:** Message-ID and all trace/routing headers (sender- or route-controlled, differ per recipient path); To/Cc/Bcc (per-recipient); attachments and HTML bytes (v1 scope is the text the user read and judged).
- The domain-separation prefix keeps it disjoint from every other 32-byte id (content CIDs, `content_id_for_document`, chunk hashes).
- **One definition, shared Rust:** the canonicalizer + hash live in `libs/fauna-mail` (a sibling of the tokenizer), exposed to the Go MTA over the existing FFI (priority #2). No Go reimplementation.

**Where it is computed:** once per message, pre-seal, at whichever sanctioned position holds the delivery-time plaintext (`content-scoring.md` § The two plaintext positions): the **MTA perimeter** at the DATA stage for external inbound and MTA submission, and the nest's own **in-domain seal-and-ingest path** for first-party client submissions (the same trust position as an MTA submission — the caller holds the plaintext, and the nest already parses the same subject/body fields there for the index hint). It rides `IngestInboundMailRequest` additively (`#[serde(default)]` — old bridges send no hash; those messages simply cannot aggregate) and lands as floor metadata in the segment footer plus the SQLite mirror; the relay's sealed-verbatim append forwards the source floor's hash unchanged. The nest never *unseals anything* to compute it, and the client never needs to (the flag paths resolve the stored hash by message id). Resting the hash for **every** message, reported or not, is what the transition-time attach and the late-copy ingest join read (§ The aggregate) and what keeps the hash nest-attested; its at-rest cost is the guess-and-confirm residual accepted in § Threat model & accepted limitations.

**Posts:** a post's id is already content-addressed (CIDv1 dag-cbor blake3-256, `bins/fauna-nest/src/db/posts.rs`) and identical on every nest holding the same post object — it *is* the report-hash for posts. No new hash is minted for them.

**Conversations are out of scope permanently** (MLS wall — the nest never sees plaintext to hash, and a conversation message has no cross-nest identity by design).

**Honest v1 limitation — exact match only.** A spammer who mutates the body per recipient (unique tokens, homoglyphs) defeats exact-match aggregation entirely. This is a **bounded non-goal**: v1 measures whether the exact-match signal (mass identical campaigns, forwarded chain letters, repeated phishing templates) is valuable at all; near-duplicate matching (shingling / similarity hashes) is a revisit *only if it proves so*, and it changes the privacy analysis (a similarity hash leaks more about content than an exact hash), so it re-enters through a frame-level design pass, not a drive-by upgrade.

## Report capture — existing gestures only

No new user gesture. The two existing explicit mark-as-spam paths gain a side effect, **iff** the reporter opted in:

| Path | Gesture | Content identity resolved via |
|---|---|---|
| `fauna.moderation.train {verdict:"spam"}` | the client's mark-as-spam on a post | the post id (content-addressed) |
| `fauna.bridges.put_spam_model {history_op: Insert{label: Spam}}` | MDA `\Junk` (STORE/MOVE from any IMAP MUA, or the Fauna app's mail button) | the stored `report_hash` for that `message_id` (mirror lookup; absent → no report, graceful) |

- **Opt-in state:** a new `spam_preferences.share_reports INTEGER NOT NULL DEFAULT 0` column (additive migration), beside `contribute_baseline`. Set via `fauna.moderation.report_share.set`; default **off**.
- **Write:** an opted-in spam-train inserts `content_reports (content_hash, factor='report:spam', reporter=actor, content_kind, created_at)` — idempotent (`PRIMARY KEY (content_hash, factor, reporter)`; flagging twice is one report).
- **Symmetry:** a ham-train / an undo of a spam lesson (`put_spam_model`'s `history_op: Delete`) on the same content **deletes** the reporter's row and recounts — a withdrawn judgment leaves no residue.
- **Opt-out** (`share_reports → 0`): stops future contributions **and deletes the reporter's existing rows**; every affected aggregate recomputes immediately (may fall below k → its bus rows and export entries are withdrawn, mirroring the baseline's below-floor withhold). User-controls-their-data: revocable from the app, fully.

Reports reference content by hash only — a report row survives the message's deletion (the judgment stands; the content is gone).

## The k-anonymity choke point

- **`REPORT_MIN_REPORTERS: u32 = 3`** — a hard-coded shared-Rust constant (`libs/fauna-core`, beside the `ScoreEntry` types), the sibling of `BASELINE_MIN_CONTRIBUTORS`. Like that floor it is a **safety constant, deliberately not a knob** on any surface (app or otherwise): it is a privacy floor, not a preference (decided for the baseline with the user 2026-07-01; the same reasoning transfers verbatim).
- **One gate function** — `exposed_report_count(local_count) -> Option<u32>` (`None` below k) in shared Rust — and **every** read surface routes through it: the bus-row writer, the federation export, `report_share.status`, all of them. There is **no other read surface at all**: no RPC (admin included) SELECTs `content_reports`, and no reply anywhere carries a reporter identity or a below-k count. New surfaces must consume the gate function, never the table.
- **The table, gate, curve and federation pair are factor-parametric, not spam-only.** [`../behavior/engagement-cues.md`](../behavior/engagement-cues.md) § Layer B rides this identical `content_reports` schema, k-gate, score curve, and `fauna.federation.reports.{exchange,export}` pair for its own opt-in `signal:watch-complete` / `signal:skip` per-item verdicts — no new table, no new federation kind. That doc owns the signal vocabulary + capture semantics; this doc owns the shared plumbing every factor (`report:spam` included) routes through.
- **At-rest honesty:** the raw rows exist on the nest's own disk, in the same trust class as all deployment-data floor metadata (the box owner can read the SQLite file — true of every floor table). The k-gate is a *serving-surface* guarantee, structural against every wire/RPC/export; the at-rest exposure is bounded to hash+reporter (no content) on the reporter's **own** nest, which is the frame's stated boundary ("individual reports live only as caller-scoped rows on the reporter's own nest").

## The aggregate — a tier-3 bus factor

At ≥ k local reporters (and on later transitions: new reports, opt-outs, peer imports), the aggregate lands on the scores bus (`content-scoring.md` § The scoring-metadata bus) as `ScoreEntry { factor: "report:spam", score, tier: 3, scorer_version }` rows in `content_scores`.

**Score-from-count curve** (integer per-mille, no floats on the wire or in the row):

```
local_pm(n)  = 0                     if n < REPORT_MIN_REPORTERS
             = min(1000, 200 + (n − 3) × 17)   otherwise
score        = min(1000, local_pm(n) + (peer_bucket_present ? 100 : 0))
```

- k = 3 reporters → **200‰** (modest — three judgments are a hint, not a verdict); the ramp saturates at **~50 reporters → 999–1000‰** (beyond ~50, more reporters add nothing — the signal is already as strong as it gets).
- **The peer bucket is flat 100‰, present-or-absent.** All peer aggregates for a hash collapse into **one** non-scaling corroboration bucket (`federation.md` § Federation residue surface, the Report exchange/export row — `nest_id`s are self-minted and free, so claimed counts and peer multiplicity must buy nothing). A peer-only signal (zero local ≥k consensus) is exactly 100‰ — visible corroboration, far below any plausible act threshold. Local reporters, who are scarce real accounts, are the only thing that scales.
- `scorer_version` starts at 1 and bumps on any curve change. The factor is deliberately **not** in the model-version registry (`builtin_factor_versions`): the nest itself is the scorer — it rewrites the rows on every aggregate transition — so a registry entry would create re-score obligations no capability-holder can serve. A curve bump therefore recomputes nest-side (on the next aggregate transition per hash; a proactive full sweep can accompany the bump commit if ever needed).
- The factor composes like any other bus factor (`content-moderation-and-ranking.md` § Composition) — no special-casing in feeds; it is a *signal*, not a labeler (distinct surface from the `fauna.labelers.*` registry on the same bus).

**Attaching to items:** `content_scores` keys on the per-copy storage `content_id`, while the aggregate keys on the report-hash — so the writer joins through the mirror: at every aggregate transition it writes/refreshes (or withdraws, below k) one row per local item carrying that hash, and mail **ingest** of a new item whose hash already has a live ≥k aggregate writes the row immediately (late copies of a known campaign are scored on arrival). Both writers consume the gate function.

## Federation exchange

Two nest-to-nest kinds on the federation channel (nest-signature auth, open-federation — not `is_paired`-gated, per-origin throttled):

| Kind | Payload | Semantics |
|---|---|---|
| `fauna.federation.reports.exchange` | `{ epoch, entries: [{ content_hash (hex), factor, count }] }` → `{ imported }` | a peer pushes its ≥k aggregates. Hard cap `MAX_REPORT_EXCHANGE_ENTRIES = 1024` per request. Upsert into `peer_content_reports` keyed `(content_hash, factor, peer_nest_id)` — latest epoch wins per peer; never touches `content_reports`; recomputes affected bus rows. **Factor allow-list:** only the exchanged family — `report:spam` and the `signal:{watch-complete,skip}` cue aggregates (`fauna_core::scoring::reports::is_exchanged_factor`) — is accepted; an entry naming any other factor is skipped (not an error, so a newer peer's additive factor never fails the batch) and writes nothing, so the exchange can never replace a perimeter verdict, a labeler's row or any other bus factor (a peer holds no `content.label-write`). |
| `fauna.federation.reports.export` | `{}` → `{ entries }` | serves **this nest's local aggregates only**, each `count` a *local* reporter count that passed the gate function. Highest-count first, bounded to the exchange entry cap (an export is always importable whole). |

- **No laundering:** exports never include peer-derived data — a count crossing the wire is always a first-hand local-consensus count from the exporting nest, so a hostile aggregate cannot be washed through an honest intermediary into looking local. (Re-export of the *effect* is inherently capped: the peer bucket contributes only the flat 100‰ locally and nothing to the export.) The gate is honored on **both** ends: an importer also skips entries whose claimed `count` is below k — a value the exporter's own gate would have withheld is not corroboration.
- **Peer storage is bounded:** reports are per-item (an unbounded universe of hashes), so `peer_content_reports` carries a per-peer row cap (`MAX_PEER_REPORT_ROWS = 10_000`, oldest-updated evicted) — a hostile peer cannot grow the DB without bound.
- Exchange cadence rides the peering triggers of the exchange originator plane; there is no push obligation — each nest holds only the aggregates of peers it chose to talk to (no central registry, structurally). The scheduler that actually originates the reports pair (and the trends pair beside it) is the **exchange originator plane**, owned by `../architecture/federation.md` § Federation residue surface (built 2026-07-13).

## Threat model & accepted limitations

- **Deliberate local sybil (the k-anonymity count sybil's sibling, accepted).** The k floor defeats the *natural* degenerate case (a lone reporter can never expose an aggregate), not a *deliberate* sybil: a nest whose admin (or a user able to enroll accounts) controls k accounts can fabricate any aggregate. A count floor cannot distinguish sybils from honest reporters without identity assumptions Fauna does not make. Consequence, not patch: **a nest's exported aggregate is only as trustworthy as that nest** — which is exactly why importers cap every peer at the flat non-scaling bucket. The floor is a privacy floor for the honest-majority case, not a hard guarantee against a motivated on-nest attacker.
- **Hostile peers.** Claimed counts don't scale (flat bucket); multiplicity doesn't scale (one bucket across all peers); volume is bounded (entry cap per request, row cap per peer); replay is harmless (latest-epoch upsert per peer); factor reach is bounded (the exchange's factor allow-list, § Federation exchange — a peer naming `clamav`, `labeler:*` or any non-exchanged factor writes nothing).
- **Report poisoning (flagging legitimate content).** Poisoned aggregates *inform* through the user's own thresholds — nothing is removed or blocked by this factor (informs-never-compels; mail-perimeter policy remains tier 2's). Reaching k requires k real local accounts, and every reporter's opt-out or ham-correction subtracts.
- **Membership-oracle residual (accepted by design).** An exported `(hash, count)` confirms to a peer that ≥k users on this nest saw and flagged that exact content. That disclosure **is the product** — a voluntary, aggregate, k-anonymized judgment about (in practice) unsolicited bulk content. Below-k content leaks nothing; reporter identity leaks nowhere at any count; a hash of genuinely private content never crosses unless ≥k separate local users each independently flagged the identical text *and* opted in.
- **At-rest guess-and-confirm residual (accepted 2026-09-27).** `report_hash` is *unkeyed* blake3 over the canonical subject + body, computed for **every** mail whatever the opt-in, and rests in the plaintext floor (segment footer + the `segment_records.report_hash` mirror; the relay copies it to the paired replica) — so it reaches every reader of the floor: the box owner, a disk thief, a replica holder. To such a reader it is an **exact-text oracle**: they can confirm a guessed canonical text, and brute-force one whose only unknown part is guessable to the character (a templated one-time-code mail, a fixed notice), for a message whose existence, timing and envelope FROM the floor already shows. It discloses nothing about text the reader cannot guess exactly — the v1 exact-match limitation cuts both ways: per-recipient content (a name, a unique link token, a high-entropy code) defeats the guess as it defeats aggregation — and nothing on any wire, where every serving surface stays behind the k-gate. **Why accepted rather than fixed:** the mechanism needs the hash *resident and nest-attested for unreported mail* — the aggregate writer attaches a newly ≥k aggregate to every earlier, still-unjudged local copy through the mirror join, the ingest join scores late copies on arrival (§ The aggregate), and the flag paths resolve the hash by message id so a client can never report a hash of content it did not receive (§ Content identity). Keying it per nest defends nothing against the disk reader who holds the key too and cannot be translated to the cross-nest unkeyed form without the plaintext; sealing it, or computing it at report time from the reporting client's unsealed copy, breaks the attach, the late-copy join and the nest-attested binding. Each is a frame-level mechanism change, not a hardening, and none is planned. **Bound:** exact-match confirmation only, at rest only, to the same reader class the `content_reports` rows already concede (§ The k-anonymity choke point → *At-rest honesty*). The floor entry lives in `../architecture/encryption-at-rest.md` § Plaintext floor and its Mail body row.
- **Exact-match evasion** — see § Content identity; a bounded non-goal in v1.
