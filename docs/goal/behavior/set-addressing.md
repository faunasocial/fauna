# Set addressing — how a request names a folder set

Status: ratified 2026-10-11 (design pass; refutable advisory, no live deployment affected); the row form is built nest-side on every per-set kind and stamped by the sync engine, the backup mirror, the Media page's upload, restore and delete, and the custody ingest's key read — § Implementation status today

## The forms

**A set's name is a label, not a key.** The nest keeps a name unique only per owner (`UNIQUE(name, actor_id)`), so a user who owns a set and is a member of another of the same name holds two sets one name cannot tell apart; `on-demand-files.md` § Hosting multiple on-demand folders rules that every client seam telling one engine from another keys on the set's `FolderRef`, and this doc carries that rule onto the wire. A per-set request — one that acts on a set it names — carries its address in one of four forms, and every form but the first two names exactly one row:

- **The name** (`folder` / `name`): the plaintext label. Both same-nest name resolvers run an owner-first search — the caller's own row of that name, then a group-bound set of that name whose roster admits the caller — so a member's own same-named set is found before the shared one, which is the shadow this doc closes. The name still travels for a reserved `__` set, which the nest routes on its literal name, and for the creates and the update that rest a name (`path-sealing.md` § the set-name plane).
- **The hash** (`name_hash`): `set_name_hash(name)`, the address a sealed set is found by once its name rests blank, stamped by the client funnel; it runs the same owner-first search as the name — the hash of a shared name is as ambiguous as the name.
- **The row** (`folder_id: Option<i64>`): the nest's `folders.id`, `FolderRef::Local(id)` — the one same-nest form that names a row and not a name. Ruled below.
- **The channel** (`nest_url` + `channel_id`): a cross-nest set's address — the derived `ChannelId`, relayed through the member's own nest to the home nest, which resolves it to the one row its claimant owns (`claimed_folder_for_channel`). A foreign set has no row on the member's nest and a channel is already an identity, so the row form never applies to it and the channel form is untouched here.

## The row form (ruled 2026-10-11)

**Every per-set request carries the row slot.** Every request type behind the protocol's `SetAddressed` trait — the `set_addressed!` and `optional_set_addressed!` lists in `fauna_protocol::folders`, plus the update request — gains an additive `folder_id: Option<i64>` (`#[serde(default, skip_serializing_if = "Option::is_none")]`) beside its name forms, never in place of them; the one set-addressed request without it is `folders.create`, which names a set that has no row yet. The slot is part of the trait's contract (`folder_id()` / `set_folder_id()`, the create's a `None` / no-op pair, and `address()` → `SetAddress::Row(id)` when a row is carried, else `SetAddress::Name { name, name_hash }`), so a request type cannot be set-addressed without it and the funnel stamps it without knowing the kind; a request addressed by a conflict id, a version or a ref list (`conflicts.resolve`, `versions.{get,undelete}`, `serve.announce`) is not set-addressed and is unchanged.

**The row wins; the name forms are not consulted beside it.** A request carrying `folder_id` resolves by that row alone: the nest loads the row by id and admits it under the kind's own gate — owner-only, writer (the owner or a `writer` member), or reader (the owner or a roster member) — exactly the gate the kind has today, and answers the same `not_found` fold for an absent row, a row the caller may not reach under that gate, and a row of the wrong kind (ST-RES-1: a probe by id learns nothing a probe by name would not). It never falls through to the name forms when the row names nothing admissible — that fall-through would be the shadow itself — and it never cross-checks the name forms against the resolved row: the ref is the key and the name a label (`on-demand-files.md`), so a stale label beside a live ref must not refuse the request. On the record kind the row arm never provisions a reserved backup set: a ref names an existing row by construction. A request without the field resolves by name, owner-first, as it always has.

**Three resolvers, one address.** The nest's three same-nest resolvers — the reader's and the writer's in `folder_authz` and the owner-only lookup the handlers share — each take the request's address, a row or a name with its hash, and each has its by-ref arm; the handler reads the address off the request through the trait, so no handler picks a form by hand. The reader's by-ref arm exists (the chunk GET hint, `relay-serving.md` § Relay serving, step (4)); the writer's and the owner's are the build.

**Whoever holds the row sends it.** A sender that knows the set's row stamps it on every per-set request, through the one client funnel: `fauna_protocol::folders::addressed` grows a row-aware form, `addressed_at(req, Option<FolderRef>)` — a `Local(id)` fills `folder_id`, a `Foreign` fills nothing (the channel form is already on the request), then the hash is stamped and the name taken off as today — and the wrapper crates (`fauna_client_sync::SyncClient`, `fauna_client_folders::FoldersClient`, the media machine's nest API) take the row beside the name on every per-set call. The senders, by what they hold: the **sync engine** holds its binding's `FolderRef` (`SyncEngine::with_folder_ref`, set by the lifecycle for every engine it builds and by the binding edge) and stamps it on every per-set kind it sends — `changes.list`, `changes.record`, `changes.supersede`, `lease.{acquire,release}`, `conflicts.report`, `folders.update`, `web.files.prune_sealed` — the owner's engine as much as a member's (the row is known, and the nest resolves identically); the **backup mirror** holds the covered folder's id; the **custody ingest** resolves a same-nest set's address from the folders list by channel and holds the row there, and stamps it on `content_key.get`, where a same-named own set otherwise answers the wrong set's envelope (fail-closed today only because the envelope's signature then fails under the shared channel); the **Media page** sends the row of a shared set it uploads into, lists and deletes from, and a restore sends the restored version's own row, which the nest stamps on every listed version (`FileVersionInfo.folder_id`, `file-versions.md`) (`../ui/media.md` § Encryption at rest → *The filter and the upload target address the row*); the **agent's versions read** holds the binding's ref. A sender holding no row — an app addressing an own set by name, a folder-less client's restore, a reserved set — sends the name forms alone; an owner's names are unique, so for an own set the name is still a key. **A sender that signs what it sends binds that row's nonce:** a writer-signed record carrying `folder_id` is signed under the nonce of the row it names, resolved by the row (`FolderKeyResolver::set_nonce_ref`, the funnel `fauna_client_sync::SetNonceSource::lookup_at`), never by its name — the nest verifies the record under the row it lands in (`writer-signed-change-records.md` ruling (2)), and a name lookup beside a same-named own set answers the own set's nonce, which the nest refuses as `change record signature does not verify`; a resolver with no by-row answer falls back to the name.

**The nudge is not an address.** `PushEvent::SyncChanged` names the set by name and hash and asks every engine matching it to pull; a same-named pair's two engines both pull, each listing by its own row — an extra pull, never a wrong one.

**Compatibility.** Additive both ways: a nest that predates the slot ignores it and keeps the owner-first answer — wrong only in the same-named-member case the slot exists for, and the product is 0.1.x, where no wire compat is owed (`../architecture/version-compatibility.md` § Dimension 2, the fifth exception); a client that predates it sends the name forms and gets today's answer. Nothing is removed: the name forms stay the address of a sender holding no row.

**Refused.** (1) A `folder_ref` wire string in place of `folder_id`: the channel form already carries the foreign arm, and `i64` is the shape the replies (`SyncChange.folder_id`, `MediaItem.folder_id`) and the deposit kinds already use for a row. (2) A same-nest `channel_id` form: a channel names a shared set only, an own set has none; the row names both. (3) Checking the name forms against the row: a label must not veto a key. (4) Limiting the slot to the kinds with a shadow today: the shadow follows the owner-first search, which every by-name kind runs, so a kind without a shadow today gains one the day it admits members.

## Tests

- **Nest conformance** (`bins/fauna-nest/tests/conformance_shared_folders.rs`, the real router): a writer W who owns `photos` (row 7) and holds `writer` on O's `photos` (row 9). By name, W's record lands in 7 — the shadow, pinned as the behaviour of a rowless request. With `folder_id: 9`: the record lands in 9 (`changes.list { folder_id: 9 }` returns it for O and for W; `{ folder_id: 7 }` does not), `lease.acquire { folder_id: 9 }` leases 9 (its `FolderSummary.lease` names W's device; 7 stays unleased), `conflicts.report { folder_id: 9 }` files on 9 (O's `conflicts.list` shows it), `changes.supersede { folder_id: 9 }` from W is refused owner-only as today; a reader R with `folder_id: 9` on each write kind, a stranger, and a row that does not exist all answer `not_found`.
- **Engine unit** (the fake nest): an engine built `with_folder_ref(Local(9))` stamps `folder_id: Some(9)` on every per-set request it sends; one built without a ref stamps none; a `Foreign` ref stamps none and keeps the channel form.
- **Two-plane capstone** (the harness of `writer_member_and_owner_round_trip_edits_both_ways_two_engines`): W's real engine, bound to row 9 while W owns row 7, round-trips an edit into O's replica, and row 7's change log stays empty.
