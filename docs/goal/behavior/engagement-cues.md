## Goal

A user scrolls their feed. Their app notices — locally — which posts they lingered on, which videos they watched to completion, which items they skipped. Those cues (a) train the user's own sealed tier-1 topic factors, so their feeds get better without telling anyone anything, and (b) accumulate in a sealed per-item rollup synced through their nest for cross-device continuity. If — and only if — the user flips the default-off sharing toggle, their app additionally contributes coarse per-item verdicts (watched-to-completion / skipped) to the same k-anonymized aggregate plane as spam reports: nothing about them is readable anywhere until ≥ k distinct local users produced the same verdict about the same item, and only `(content-id, factor, count)` ever crosses any boundary.

## The two layers (frame D6, ratified 2026-07-12)

| Layer | What moves | Privacy class | Rule |
|---|---|---|---|
| **A — private** (default, no opt-in) | raw cues → derived verdicts → the user's own sealed tier-1 models + sealed rollup | tier-1, sealed under the user's key, nest-opaque | never leaves the user's control; the nest stores only an opaque blob |
| **B — shared** (opt-in, default off) | coarse per-item verdicts → k-anonymized aggregates (`signal:*` bus factors) | tier-3 transparent **aggregate**; individual contributions live only as caller-scoped rows on the contributor's own nest, below k nothing is readable anywhere | every `report-sharing.md` invariant verbatim: k ≥ 3, `(content-id, factor, count)` only, per-nest aggregation, peer-to-peer exchange, non-scaling peer bucket, informs-never-compels |

**The hard line (the frame's revised rule):** a per-user implicit event stream — raw timings, dwell durations, watch percentages, identity-attributed behavior — never crosses a user boundary and never rests in plaintext off the user's device. Layer B shares *verdicts about content*, never *behavior of users*.

## Cue vocabulary & derivation — shared Rust, client-side

- **Raw *geometry* is app glue; everything downstream is shared Rust (boundary revised 2026-07-29 — one layer lower than the 2026-07-12 original).** A capture shell owns only what is genuinely platform-bound: the per-row geometry probe (each measurable row's `(post_id, top, height)` plus the viewport bounds, all in any one coordinate space), the sampling-tick + extra-sample-on-scroll scheduling, lifecycle (construct on wire-up, drain on leave/navigate-away), and handing the returned observations to the manager + surfacing errors. **All bookkeeping between the probe and the manager — visibility bucketing, per-sample credit arithmetic with its stall cap, the hold-vs-leave policy, the single-sample noise floor, `is_media` stamping, `Observation` assembly — is the shared `CueTracker`** (`libs/fauna-feed`, beside `CueEngine`), and all *derivation* below that is `CueEngine`, so neither thresholds nor honesty policy can drift per app. A shell MUST NOT re-implement the bookkeeping or bucket dwell at any fraction itself. *(Why revised: the 2026-07-12 "raw observations are app glue" line was drawn before any shell existed; four per-app reimplementations of the identical arithmetic then accumulated — linux/windows/android/apple, byte-identical constants, hand-mirrored doc comments — and had already drifted on a semantic point: windows and android fed the wall clock into dwell credit, linux and apple the monotonic clock, so a date change inflated dwell on exactly two of four platforms. The drift the original rule existed to prevent was happening one layer below where it drew the line.)*
- **The `CueTracker` contract:** `sample(rows, window_post_ids, viewport_start, viewport_end, mono_now_ms, wall_now_ms) → Vec<Observation>` plus `drain_all(wall_now_ms)` (page-leave: everything tracked has left). `window_post_ids` is every post currently in the loaded window, not just the realized rows — the `HoldUnmeasured` leave rule below is defined against it, so the ratification's original parameter list (which omitted it) could not express its own rule; corrected when the core landed. A `rows` entry carries `(post_id, top, height, is_media)` plus an `Option<u32>` peak-playback per-mille the tracker folds by `max` into `Observation::media_played_pm` — every shipped shell renders feed media as still images and passes `None`, but a UniFFI record field-add breaks every Kotlin/Swift/C# construction site, so the field ships with the face rather than after it. Per-sample credit = elapsed **monotonic** time, capped at `CUE_MAX_SAMPLE_CREDIT_MS` (1 000 ms — a stalled loop credits nothing it didn't paint) and bracketed by measurements (an empty probe read resets the baseline: credit only ever spans between two successful samples). A row with non-positive height is unmeasurable — held, never a fabricated 0-visibility reading. An exposure confirmed by a single sample is dropped at emit (`CUE_MIN_VISIBLE_SAMPLES` = 2 — image-load layout shifts flash cards through the viewport for one tick; those are not exposures). Two clocks by contract: the monotonic clock feeds credit (an NTP step or user date change can never inflate dwell), the wall clock only stamps `observed_at_ms`. The one genuine platform divergence is typed, not prose: **`LeaveModel::HoldUnmeasured`** (eager/retained containers — a tracked row leaves only on positive evidence, i.e. measured below skip-visibility or gone from the loaded window; linux's GTK `ListBox`, windows' non-virtualizing `StackPanel`, apple's eager `VStack`) vs **`LeaveModel::AbsenceIsLeave`** (virtualizing containers — absence from a non-empty measured set means the row was disposed, hence left; android's `LazyColumn`). Native shells reach the tracker via `FfiCueTracker` (UniFFI, `feed-manager`-gated), web via `WasmCueTracker`; the sampling cadence is the shared `CUE_SAMPLE_INTERVAL_MS` (250 ms), read through the tracker face, never re-declared.
- **v1 derived verdicts (deliberately coarse — two, not twenty):**
  - `watch-complete` — media played ≥ `CUE_COMPLETE_FRACTION` (0.85) of its duration, or a non-media post held ≥ 75 % visible for ≥ `CUE_DWELL_LONG_MS` (8 000 ms).
  - `skip` — the item was ≥ 50 % visible for < `CUE_SKIP_MS` (1 200 ms) before scrolling on, **and** the surrounding session shows normal reading pace (a fast-scroll burst derives nothing — flick-throughs are not judgments).
- **The media arm of `watch-complete` is DEFERRED (declared 2026-10-01).** No goal doc ratifies a feed surface that plays video inline: a video in a post is a thumbnail ([`../architecture/render-model.md`](../architecture/render-model.md) D6b), and tui declares inline playback a platform absence ([`../architecture/apps/tui.md`](../architecture/apps/tui.md) § Declared platform absences). So no app can produce a played fraction, every shell passes none (§ Implementation status today), and `watch-complete` is reachable through its dwell arm alone. What stays built is the derivation, its constant and the `media_played_pm` field (it ships with the face for the reason the `CueTracker` contract gives). What is deferred is the **promise**: "a video watched to the end teaches more like this" is no user-facing outcome, and no feature-catalog outcome, until a goal doc ratifies inline playback in the feed — that surface's own decision, with its own element IDs under rule A, never this doc's. The arm then goes live by a shell passing the fraction it already has a field for; nothing here needs re-ratifying.
- Constants are hard-coded Rust (bucket 1). The vocabulary is additive: a future cue kind is a new derived verdict + rollup field, never a schema break.
- **Verdicts are per-(user, item), idempotent, last-wins** — re-watching flips a `skip` to `watch-complete`; there is no event *stream*, only a current verdict per item.

## At rest — the sealed cue rollup (frame D9)

- **Shape:** `CueRollup { items: BTreeMap<content_id, ItemCues { verdict, watch_ms_total, completions, last_at }> }`, capped `CUE_ROLLUP_MAX_ITEMS = 4096` (oldest `last_at` evicted), serialized additively.
- **Seal + home: exactly the topic-model precedent** (`topic-factors.md` § At rest, which owns the plane's seal key; the rollup inherits whatever the shared pipeline writes): sealed via the shared model byte-seal pipeline (`seal_model_bytes`; the `__config` blob that once shared its BackupKey ancestor retired 2026-10-02 — [`../architecture/config-dissolution.md`](../architecture/config-dissolution.md) § The `__config` dissolution schedule → *The closure order*, step (6)), stored verbatim-opaque in the existing **`personalization_models`** table under factor key **`cues:v1`**, synced via the existing `fauna.personalization.model.{fetch,put,delete}` wire (the nest-side put validation extends its accepted prefix set from `topic:` to `topic: | cues:` — additive). Same 512 KiB blob cap; fetch-on-session-start, put-on-batch (batched, not per-scroll — a put every `CUE_PUT_DEBOUNCE_S`, 120 s, or on background/close).
- **Why on the nest at all (vs. device-local):** cross-device continuity (D9) — the phone's watches inform the desktop's feeds — and reinstall survival. The box owner reads nothing: the blob is opaque, and the *existence* of a `cues:v1` row discloses only "this user's client captures cues", the same visibility class as owning a topic model.
- Deleting the row is the user's own delete affordance (Personalization home), user-revocable by construction.

## Layer A — the private training feed

Derived verdicts feed the user's sealed tier-1 topic factors through **`topic-factors.md`'s v2 engagement-training mechanism** (that doc owns the weighting shape; this doc owns the cue vocabulary it consumes): a `watch-complete` trains a **weak positive** example into each trained factor with `learn_from_engagement = on`; a `skip` a **weak negative**; both only where the item's text is still fetchable, both reversible via the verdict flip. Everything runs on the user's client post-decrypt (tier-1 self-servicing); the nest is never involved beyond storing sealed blobs.

## Layer B — opt-in k-anonymized contribution (the `signal:*` factors)

- **Opt-in state:** `spam_preferences.share_signals INTEGER NOT NULL DEFAULT 0` (additive column beside `share_reports` — that table is the de-facto per-user moderation-preferences row; the name is historical). Set via **`fauna.moderation.signal_share.set { share }`**; status via **`fauna.moderation.signal_share.status`** returning the published-aggregates transparency view (byte-identical to the export, the `report_share.status` precedent). Opt-out deletes the contributor's rows and recomputes — withdrawal semantics verbatim from `report-sharing.md`.
- **Write path:** an opted-in client submits verdict transitions — **`fauna.moderation.signal_contribute { content_id, signal: "watch-complete" | "skip" | "withdraw" }`** (User-class, caller-scoped). The nest inserts into the existing **`content_reports`** table with factor `signal:watch-complete` / `signal:skip` (posts key by post id, the report-sharing posts convention), `PRIMARY KEY (content_hash, factor, reporter)` idempotent; a verdict flip withdraws the old factor's row and inserts the new; `withdraw` deletes both. Public posts only — a verdict about restricted content is rejected at the handler (its existence would leak readership).
- **The aggregate:** at ≥ `REPORT_MIN_REPORTERS` (= 3 — the same constant, same gate function, no new floor) the aggregate lands as bus rows `ScoreEntry { factor: "signal:watch-complete" | "signal:skip", score, tier: 3 }` via the same count curve as `report:spam`, and joins the **existing** `fauna.federation.reports.{exchange,export}` pair unchanged — both `signal:*` factors are on the exchange's factor allow-list (`report-sharing.md` § Federation exchange), the flat non-scaling peer bucket applies verbatim (signals get **no** trend-style ramp: they are per-item judgments like reports, not presence corroboration). No new federation kinds, no new tables.
- **Composition:** the factors compose like any bus factor, through each user's own weights — a quality-seeking feed weights `signal:watch-complete` positive and `signal:skip` negative; nothing is compelled. `trending.md` v2 MAY fold them into the trend curve (its decision).

## Threat model & accepted limitations

- **The rollup blob is an existence oracle** (a `cues:v1` row says this user captures cues) — same accepted class as owning a topic model or muted-keyword list.
- **Layer-B verdicts are behavioral at aggregate grain.** A ≥k `signal:watch-complete` aggregate on a niche public post still says "≥3 users here watched this to the end" — the membership-oracle residual, accepted for public posts exactly as for reports; restricted content is excluded at the write path.
- **Gaming:** k local sybils can fabricate `signal:*` aggregates — accepted; importers cap peers at the flat bucket; the factors inform through user-chosen weights only.
- **Derivation noise:** dwell/skip heuristics misfire (background tabs, interruptions). Accepted: verdicts are weak signals feeding statistical models and k-gated aggregates; no verdict has per-item consequences.
