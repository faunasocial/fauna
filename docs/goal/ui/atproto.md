## Goal

One page answers one question: **how deep is this user's Bluesky integration?** The answer is a single ordered choice — not a pile of toggles — and every Bluesky control the product has lives on this page as a sub-setting of the level that makes it meaningful. The four levels:

| Level | Meaning | Identity backing |
|---|---|---|
| **Off** | no ATProto presence | none |
| **Linked account** | read/interact/cross-post via an existing external Bluesky account | the user's external DID, on bsky.social or another PDS |
| **Hosted here — visible** | this nest mints and holds the DID; public posts project one-way; the network can read/follow/interact | a Fauna-hosted DID (the S-chain) |
| **Hosted here — full PDS** | additionally, third-party ATProto apps log in against this nest | the same Fauna-hosted DID (the F-chain) |

Why one ordered selector: the two identity backings are *alternatives* — a Fauna user picks exactly one ([`../behavior/atproto-pds-bridge.md`](../behavior/atproto-pds-bridge.md) § Relationship) — and independent toggles would let a user hold both at once. The selector makes the exclusion structural, and the upper two levels are genuinely ordered (full PDS needs the identity and repo the visible level creates). The page is dedicated — the Nostr precedent for a deep integration ([`../behavior/bridges.md`](../behavior/bridges.md) § Scope) — because "Fauna *is* your Bluesky home server" is at least as deep as Nostr.

- **`atproto_account_settings.integration_level`** — the additive column, defaulting to `off`, plus the § Migration step-1 derivation (consume-link → `linked`, active hosted identity → `hosted_visible`, everyone else → the absent-row `off`). The derivation is idempotent by construction rather than run-once-marked, so it can never resurrect a level the user has since stepped away from.
- **`fauna.bridges.atproto.set_integration_level`** — User-class, self-scoped, the single call per confirmed transition. Full SQL-transaction atomicity is impossible across four stores, so the ratified contract is met the way the client-state-recoverability invariant actually requires: **every effect is individually idempotent and the level is written LAST**, so a crash leaves the old level over partially-applied effects and the retry converges. A client therefore never observes a level whose effects were skipped.

## Layout & flow

Top to bottom:

1. **The depth selector** (`atproto-depth-selector`) — four ordered options, exactly one active: `atproto-depth-off`, `atproto-depth-linked`, `atproto-depth-hosted-visible`, `atproto-depth-hosted-full`. Each option carries a one-line description (the § Goal table's meaning column, in user voice). The current level is marked; selecting a *different* level opens the transition card (below) — the level never changes on selection alone.
2. **The transition card** (`atproto-depth-confirm-card`, with `atproto-depth-confirm` / `atproto-depth-cancel`) — states, concretely and completely, what this specific level change will do before anything happens (§ Transition semantics). Any level is directly selectable; a jump across multiple rungs composes the per-rung effects into one card and one confirm.
3. **The active level's panel** — sub-settings reveal per level; a level's panel renders only at (or above, where stated) that level:
   - **Linked account** → the consume-side link surface: the existing `bridge-link-form` (unlinked) / `bridge-card` (linked — settings incl. `write_through`, follows) components, reused verbatim from the Bridges page (`used_in` gains `atproto`; zero new IDs). Behavior unchanged, owned by [`../behavior/bridges.md`](../behavior/bridges.md).
   - **Hosted here — visible** → before mint: the DID-method radio (`atproto-did-method`, `-plc` pre-selected + "Recommended", `-web`), one sentence each plus the either-way handle line; the history opt-in (`atproto-history-backfill`) rides the transition card, not the panel. After mint: the identity summary — `atproto-hosted-handle` (the derived `@you.yourdomain`; the raw DID string is never shown), method, active/deactivated state. Renders at both hosted levels.
   - **Hosted here — full PDS** → the login-plane groups exactly as approved: app credentials (`atproto-app-credentials-list` component + `atproto-app-credential-mint`), connected apps (**moved** to the cross-protocol connected-apps page, [`connected-apps.md`](connected-apps.md); the `atproto-connected-apps-list` component was retired from ui.yaml 2026-10-03), the external-apps kill-switch (`atproto-external-apps-enable`), the **authoring-delegation row** (`atproto-delegation-*`, D10 — see below), and — when a consent request is pending — the consent card (F4; **moved** to the Connected apps page's requests tray, its `atproto-consent-*` IDs retired 2026-10-03). Mechanism owned by [`../behavior/atproto-pds-full.md`](../behavior/atproto-pds-full.md).

     **The delegation row answers a different question from everything above it, and the panel must not blur them:** the credentials and connected-apps groups govern who may *sign in*; the delegation row governs whether a signed-in app may *post as you*. Signing in is not authorization to author — an account at `hosted_full` with no delegation has apps that can read and refuse every write. So the row states the granted capabilities (`atproto-delegation-scope`), when it was authorized and when it lapses (`atproto-delegation-lasts-until`), and its liveness (`atproto-delegation-status`), with one control to authorize-or-renew (`atproto-delegation-authorize`) and one to revoke (`atproto-delegation-revoke`). **There is deliberately no expiry chooser** — the ~90-day window is a hard-coded constant, the shipped capability-grant shape ([`nests.md`](nests.md) § Expiry / renewal).
4. **"Delete my Bluesky presence"** (`atproto-delete-presence`) — renders whenever a hosted identity exists, active *or* deactivated (so it stays reachable after stepping down to Linked/Off). Confirming opens its own confirm card (`atproto-delete-confirm-card`, with `atproto-delete-confirm` / `atproto-delete-cancel` — distinct from the depth selector's transition card) before the destructive sweep runs. The card carries the terminal opt-in `atproto-delete-tombstone` — "also permanently retire this identity", never pre-ticked, greyed with its reason for a did:web identity or a did:plc not yet published; ticking it replaces the card's identity-kept line with the cannot-be-undone one. Semantics owned by [`../behavior/atproto-pds-bridge.md`](../behavior/atproto-pds-bridge.md) § Disable & revocation layer 2.

**Reveal/greying rules:** the two hosted options are greyed, with a one-line reason, unless `resolve_handle_domain(domain).is_public_dns_name` (the real-domain gate). **Off and Linked are never gated as LEVELS** — both stay selectable on any box. Since 2026-09-02 the same real-domain predicate does govern one thing *inside* Linked: the OAuth **link control**, because the `client_id` Bluesky's authorization server must fetch by name derives from that domain ([`../behavior/bridges.md`](../behavior/bridges.md) § Implementation status today). On a domainless/localhost/IP box the level still opens and the control still renders — disabled, with the nest's own reason in `bridge-link-blocked-reason` — which is the § A bridge that cannot be linked right now rule doing its ordinary job, not a new per-app behavior: the nest sends `available: false` + `error`, and the shared `link_block` renders it. A **linked** account is unaffected. The DID-method radio renders only when no hosted identity exists yet — after mint the method is a fact, displayed not chosen (switching methods is a new identity, not a setting). The full-PDS option is never greyed relative to visible: it is directly selectable, composing the mint into its card if needed.

**Navigation:** settings-rail sub-page after Nostr ([`settings.md`](settings.md) § Navigation model owns the slot); nav id `atproto` — the page key (renamed with it 2026-09-28 from `bluesky`, on all 7 apps and the e2e nav).

## Transition semantics

The level is **stored user intent** (nest state, § State & data shape), changed only by an explicit confirm on the transition card. Every transition is **one atomic nest-side operation** — the client sends the target level (plus the mint parameters when entering hosted) and the nest performs all effects transactionally; a client crash mid-transition leaves either the old level or the new level fully realized, never a half-state (the client-state-recoverability invariant). What each move does:

**Upward:**

| From → To | Effects | Card copy must say |
|---|---|---|
| Off → Linked | None (reveals the link form; linking itself is the existing OAuth flow, a separate act). No card needed — this is the one effect-free transition; apply immediately on select. | — |
| Off/Linked → Hosted visible | If a consume-side link exists: **unlink it** (the one-backing rule; the external account itself is untouched — it continues to exist on its PDS, merely no longer connected). Then the enable behavior owned by [`../behavior/atproto-pds-bridge.md`](../behavior/atproto-pds-bridge.md) § Enable UX: boot the bridge if first user, mint the DID (method from the radio) — or **reactivate** the user's existing deactivated identity if one exists (same DID; no new mint; radio hidden). History backfill iff `atproto-history-backfill` was checked. | That a *new public identity* `@you.yourdomain` is created (or the existing one restored); that the external account link (if any) is removed and the external account is **not** migrated — with a "bring your existing account home" pointer once inbound migration ships; the publishing consent framing (posts become publicly visible on the Bluesky network); the backfill opt-in as its own checkbox. |
| Hosted visible → full PDS | Enable the login plane for this account (level check; the plane stays inert until a credential is minted or a grant approved — default-closed). Nothing destructive. | That third-party ATProto apps will be able to log in as this identity once credentials are minted; the DM honesty line (Bluesky DMs are not end-to-end encrypted and pass through this nest in transit). |

**Downward** (each invokes [`../behavior/atproto-pds-bridge.md`](../behavior/atproto-pds-bridge.md) § Disable & revocation layer 2 — reversible deactivation; this table is the UX contract, not the mechanism):

| From → To | Effects | Card copy must say |
|---|---|---|
| Full PDS → Hosted visible | Suspend the external-app plane: live sessions revoked, grants suspended; credential/grant rows are **kept**, listed, individually revocable; stepping back up restores usability. Projection continues. | Apps stop working immediately; nothing is deleted; reversible. |
| Hosted (either) → Linked/Off | Layer-2 deactivation: projection stops, the repo is no longer served, `#account` deactivation announced, the login plane torn down as above; the DID + keys are **retained** — re-enabling restores the same identity. Landing on Linked additionally reveals the link form. | Reversible; the network's existing copies of already-published posts cannot be recalled; "Delete my Bluesky presence" is the separate, stronger action (still visible below). |
| Linked → Off | Unlink the external account (untouched externally). Already-ingested "via Bluesky" feed content stays — it is historical content, not a live surface. | The external account itself is unaffected. |

**Not transitions:** the external-apps kill-switch (a safety control *within* full PDS — suspends the plane, the account's third-party principals included, without changing level; owner [`../behavior/atproto-pds-full.md`](../behavior/atproto-pds-full.md) § Detailed design → F1 detail); per-row credential/grant/session revokes; the delete action (below the selector, orthogonal to level).

## State & data shape

- **The level** is nest state: `atproto_account_settings.integration_level` (additive column; values `off | linked | hosted_visible | hosted_full`), per user, changed only by the transition kind. Initialization for existing users is derived once at migration (§ Migration).
- **One shared settings machine for the whole page** (decided 2026-07-22 in the S4/F1 coordination, unrefuted): `fauna-atproto-settings-machine` grows from the F1 credentials surface into the page machine — level + gate status + identity summary + link summary + the per-level panels in one snapshot, one observer loop. Two machines driving one page's levels would duplicate the level state and collide; do not build a second.
- **Snapshot** (rendered, secret-free — the F1 rule): current level; real-domain gate verdict (+ the reason string when gated); hosted identity summary (derived handle, method, active/deactivated) or absence; consume-link summary (linked identity or absence); the F1 credential/session rows; pending consent, when F4 lands.
- The consume-side link state and the login-plane rows keep their existing owners and wire shapes; the machine composes, it does not re-own.

| `atproto-delegation-revoke` | Stop external apps posting as you. Destructive: it destroys the signing sub-key. Already-published posts stay verifiable forever. | `fauna.bridges.atproto.revoke_authoring_delegation` |
| `atproto-delete-presence` | Opens the delete ceremony's own confirm card (owned by layer 2). | none (local) |
| `atproto-delete-tombstone` | Tick or untick the terminal opt-in on the open delete card. Nothing is sent: the tick rides the confirm. Greyed with its reason where the identity cannot be retired. | none (local) |
| `atproto-delete-confirm` | Perform the sweep as described on the delete ceremony's card. Confirming lands the level on **`off`**: the delete is not one of the selector's *transitions*, but a selector left parked on a hosted rung whose presence was just destroyed would offer to restore something and then not. With `atproto-delete-tombstone` ticked, once the sweep call lands the retirement is recorded — client-side consent (`tombstone_consents` in the `fauna.state.atproto-identity` rows) first, then the nest intent — and the client's converge pass publishes the PLC tombstone once it observes the sweep finished (mechanism: [`../behavior/atproto-pds-bridge.md`](../behavior/atproto-pds-bridge.md) § Disable & revocation layer 2). A retire step that fails keeps the card open with `error-message` populated; retry is safe. | `fauna.bridges.atproto.delete_presence`, then (ticked) `fauna.bridges.atproto.request_tombstone` |
| `atproto-delete-cancel` | Close the delete ceremony's card; nothing deleted. | none |
| `atproto-contest` | Open the contest confirm card, which names the op being contested, what the fork will sign, and the deadline. | none (local) |
| `atproto-contest-confirm` | Record the scoped contest intent (`contest_intents` in the `fauna.state.atproto-identity` rows, keyed to the named op's CID) and run the contest converge — build the fork from the fork point, sign with the held senior key, submit to the directory, all on the client's own connections. Failure keeps the card open with `error-message` populated; retry is safe (the directory is the durable record). | none (client-direct HTTPS to the PLC directory; NO nest call) |
| `atproto-contest-cancel` | Close the contest card; nothing signed, no intent recorded. | none |

## Persistence

The level column and every transition effect are nest state (tables owned by their feature docs). The client persists nothing about the level; the account plane's `fauna.state.atproto` and `fauna.state.atproto-identity` rows keep exactly their existing custody roles (app-credential secrets — [`../behavior/atproto-pds-full.md`](../behavior/atproto-pds-full.md) § F1; the senior rotation key + the identity-custody records beside it — `tombstone_consents`, and the contest's scoped `contest_intents` once the recovery-fork build lands, both owned by [`../behavior/atproto-pds-bridge.md`](../behavior/atproto-pds-bridge.md)). No other client-side persistence.

## Errors & edge cases

- Transition failure → the card stays open with `error-message` populated; the level is unchanged (atomicity). Retry is safe.
- Gated hosted options are disabled, never hidden — the reason line says *why* (localhost/IP domain) and what would change it.
- Same shape one level down: on a box with no public domain the Linked level's OAuth link control is disabled with the nest's reason (§ Reveal/greying rules), never hidden and never live-but-inert.
- A deactivated identity at level Off/Linked: the identity summary renders (marked deactivated) so the user can see what re-enabling restores; `atproto-delete-presence` stays reachable.
- Mint is slow (PLC round-trip): the card shows progress; the fired-on-confirm rule means no background surprise state.
- Empty full-PDS panel (no credentials yet): the default-closed framing — "no app can log in until you mint a credential".

## Don't do these

- **No standalone `bluesky-enable` checkbox** — the pre-ratification shape; it is dead. The selector is the only level control.
- **Don't read `atproto-external-apps-enable` as the depth control** — it is the kill-switch *inside* the deepest level. Its name is the most likely misread on this page.
- **Don't let two backings coexist** — no state may hold both an active consume-side link and an active hosted identity. The transition kind enforces it; the UI never offers it.
- **Don't offer the PLC tombstone as a step-down** — terminal identity destruction lives only inside "Delete my Bluesky presence" as an explicit opt-in (layer 2).
- **Don't build a second settings machine for any panel of this page.**
- **Don't grey by hiding** — gated levels stay visible with a reason; a vanished option reads as a bug.
- **Don't auto-contest, and don't gate the contest card on nest testimony** — the contest fires only on the user's explicit gesture, scoped to the named op (an auto-contester could nullify the user's own out-of-band operations), and the card renders off client-side evidence alone, so a hostile nest denying the identity cannot hide the remedy. Both rulings owned by [`../behavior/atproto-identity-custody.md`](../behavior/atproto-identity-custody.md) § The 72 h recovery-fork contest (decisions 6 and its *Where the contest's logic lives* note).
