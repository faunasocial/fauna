# fauna-mail-go

Vendored UniFFI Go bindings for `libs/fauna-mail/` (and re-exports of
`libs/fauna-mls/` and friends via `libs/fauna-ffi/`).

## Regeneration

Bindings are generated by `just mail-bridge-ffi`. Do NOT edit the
generated `*.go`, `*.c`, or `*.h` files by hand — they are overwritten
by the recipe.

## Version pin

`NordSecurity/uniffi-bindgen-go` is pinned at **v0.7.1+v0.31.0** in the
justfile recipe. This matches `uniffi @ 0.31.0` in our Rust workspace.
Upgrade rationale (spec § Library inventory): the pin trails latest by
design — `uniffi-bindgen-go` releases lag `uniffi`'s Rust side, and our
generated bindings ship as code reviewed in the same commit as a
version bump.

The bindgen is invoked via `go run @version` from the justfile recipe —
no local install. This mirrors how Go's `tools.go` idiom pins tool
versions; the source isn't vendored (cf. `libs/uniffi-bindgen-cs/`,
which is vendored only because no upstream C# binary release exists).

## Layout

Output produced by `just mail-bridge-ffi`:

- `fauna_mail/` — bindings for `libs/fauna-mail/` (parser, auth, spam,
  tokenizer, kind registry).
- `fauna_mls/` — bindings for `libs/fauna-mls/` (encrypt/decrypt
  helpers, used by I5's MDA mode).
- `fauna_<other>/` — any other namespaces `libs/fauna-ffi` aggregates
  that `uniffi-bindgen-go` emits in one pass.

## Consumer

`bins/fauna-bridges/` is the only consumer. It imports
`github.com/faunasocial/fauna/libs/fauna-mail-go/fauna_mail` (and sibling
namespaces) through a local module-replace directive in its `go.mod`.
