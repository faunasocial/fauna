# Committed grandfather baseline for tools/check-additive-evolution's rule-4
# catch-all check (transport.md § Schema and forward-compat discipline).
#
# Struct keys here are exempt from needing the `#[serde(flatten)] extra`
# catch-all. Four categories, NOT two — this list is regenerated mechanically
# (below) and so absorbs anything violating the rule at generation time
# regardless of category, which is exactly the silent-grandfather failure
# mode a verify-back
# warned about; each entry outside the first two categories needs its OWN
# doc comment on the struct explaining which of the other two applies, or
# it is an open gap, not a documented exemption:
#   1. The 2026-06-15 sweep's pre-existing exclusions. **EMPTY as of
#      2026-09-11** — this category was the un-justified residue the
#      verify-back found, and it has been fully discharged: the last of it
#      (`error::RpcError`, `error::LocalizedText`, `folders::PlaceFlags`, and
#      `bridges_ui::{AddFollowRequest, BridgeFollow, LinkRequest,
#      SetSettingsRequest}`) now carries the catch-all in code rather than an
#      exemption here. Every
#      remaining entry is category 2, 3 or 4 and carries its justification;
#      a NEW entry under category 1 is therefore not a thing that can exist —
#      re-opening it would mean grandfathering a fresh violation, which the
#      regenerator refuses to do anyway.
#   2. bridge_routing's version-locked, in-image (bridge-decoded) structs.
#      NOT the module's app-callable admin-mail kinds — the 2026-08-27
#      who-decodes ruling (transport.md:2225) pulled those under the
#      catch-all rule, and they already carry it in code, so they never
#      appear here.
#   3. The tagged-union `Unknown` fallback itself (rule 3) — not a growable
#      payload struct, so rule 4's protection is inapplicable by definition.
#   4. Whole-struct canonical-signed cryptographic statements, where the
#      signature covers the full serde encoding (e.g. `nest_rotation::*`,
#      `merge_policy::LwwStamp`) — a flatten field would change signed bytes;
#      evolution goes through a new domain-separation tag instead.
#
# Regenerate with `cargo run -p check-additive-evolution -- --update-catch-all-baseline`
# — it only ever SHRINKS this file (a struct drops out once it carries the
# catch-all or stops deriving Deserialize); it REFUSES to add an entry, so a
# genuinely new violation must be fixed, not silently grandfathered in.
